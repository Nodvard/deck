# Nodvard Deck 0.12.1: Confirmation of new server keys and fixes in the update centre

## English

The web interface is in German only for now. Names of buttons, pages, and settings are given in German as they appear, with an English translation in brackets.

### The essentials

A patch release with bug fixes and a security correction.

- **New server keys:** Deck stores them, even on existing installations, only after your confirmation.
- **Update centre:** held back and locked packages appear as their own status with an explanation.
- **Ubuntu updates:** Deck indicates when the check for phased rollout is still pending or has failed.

### What you need to do

- **Previously unknown servers:** select "Verbindung prüfen" (Check connection) on the server once and confirm the displayed fingerprint. Already known servers continue working as usual.

### Security

- **Confirmation of new server keys:** even on older installations, Deck remembers new server keys only after your confirmation. Without prompting, Deck only remembers them if you explicitly disable confirmation under "Einstellungen" (Settings) → "Server & Zugänge" (Servers & access) or via the environment variable NODVARD_DECK_SSH_CONFIRM_NEW_HOST_KEYS. This is not recommended.

### Fixed

- **Held back and locked packages:** updates that "Alle einspielen" (Install all) cannot install no longer appear as open updates. Deck displays them as "zurückgehalten" (held back) or "gesperrt" (locked) and explains the next step. If there are only held back security updates, no "Sicherheitsupdates einspielen" (Install security updates) button is displayed.
- **Installing security updates:** the run no longer removes other packages. Held back, locked, and phased security updates remain untouched. Deck checks the server again before applying updates.
- **Phasing on Ubuntu:** if it is still unknown whether Ubuntu delays updates for the server, Deck displays "Phasing noch nicht geprüft" (Phasing not yet checked) or "Phasing-Prüfung nicht verfügbar" (Phasing check not available). A pending or failed check no longer causes the notice to disappear.

### Good to know

- **Held back packages:** if other packages must be replaced or removed for them, you need `sudo apt full-upgrade` on the server. Read the list of packages apt would remove before confirming. "Alle einspielen" (Install all) leaves these updates untouched.
- **Locked packages:** a deliberately set package hold remains in place. If it was not intentional, you can remove it on the server using `sudo apt-mark unhold <package-name>`.
