# Nodvard Deck 0.13.0: Docker expansion, mobile interface, and stricter security

## English

The web interface is in German only for now. Names of buttons, tabs, pages, and settings are given in German as they appear, with an English translation in brackets.

### The essentials

A major release with new Docker features, an interface usable on phones, and multiple security tightenings. In addition, Nodvard Dock arrives as its own lean edition solely for Docker.

- **Docker:** create networks and connect containers, pull images by name, custom stack templates, sort containers, stacks from Git with scheduled checks.
- **Phone:** "Docker", "Shield", "Inventar" (Inventory), "Gameserver" (Game servers), "Meldungen" (Notifications), "Aktionen" (Actions), "Dateien" (Files), and the "Übersicht" (Overview) show their entries as cards instead of cut-off tables. The browser bar no longer hides the bottom of the page.
- **Security:** stricter content security policy in the browser, sudo runs helper scripts only in the verified version, stacks from Git connect only to the verified address, warning for unencrypted access even behind a local proxy.
- **Updates:** Deck flags security updates once in red and shows what new versions bring. The owner can approve automatic installation of security updates with password and two-factor code.
- **Nodvard Dock:** dedicated name, dedicated pages, dedicated guide. Unavailable functions are blocked even on direct requests.

### What you need to do

- **Repeat server setup once:** from the next setup onward, the sudo rule runs Nodvard Deck helper scripts only in the exact version deployed to the server during setup. Run the setup command once more on every server so that the checksum is set. Until then, servers continue running as before. Checksums do not work with sudo-rs, the default starting with Ubuntu 25.10.
- **Log in again:** browser login now exclusively uses the Nodvard Deck cookie. If you update from a version prior to 0.6.2 or have not reloaded Deck since, log in once again.
- **Git servers on your own network:** Deck now loads stacks from Git only from public addresses. For Gitea or similar servers on your home network, enable the switch "Git-Server im eigenen Netz erlauben" (Allow Git servers on local network) under "Erweitert" (Advanced) in the Docker module settings.
- **Old names in deploy/.env:** `deploy_pi.sh` automatically renames `LATTICE_*` to `NODVARD_DECK_*` on the target host and keeps a backup copy. Anyone deploying manually renames the values themselves.

### Security

- **Content security policy:** the interface blocks external sources as well as unapproved scripts and styles. Console, extensions, and file previews remain usable. Uploaded SVG logos retain their colours; oversized logos and logos with disallowed styles are rejected with clear explanations.
- **Helper scripts with checksum:** sudo executes Nodvard Deck scripts only in the exact version deployed to the server during setup. The Shield helper is bundled again during setup so that restricted sudo permissions are not unnecessarily expanded.
- **Stacks from Git:** before fetching, Deck verifies where the Git server name actually points and connects only to that exact address. Behind a proxy (HTTPS_PROXY), Deck fetches only from numeric addresses; a Git server with a hostname must be added to NO_PROXY.
- **Unencrypted access:** the warning appears even if a proxy contacts Deck via a local address or if the original client IP is missing.
- **Browser cache:** responses containing login credentials and account information may no longer be stored in the browser cache.
- **Secrets:** a changed password or token takes effect immediately across all modules, without requiring a restart.

### New

- **Docker networks:** in the "Netze" (Networks) tab, you can create a network, optionally internal only, and connect or disconnect containers. The confirmation dialog warns if a container would be left without any network afterwards or belongs to a stack.
- **Pull image:** in the "Images" tab, Docker pulls an image by name and tag, using the credentials under "Registries" for private images. If it fails, the reason is displayed.
- **Custom stack templates:** a Compose file can be saved as a template and reused for new stacks. Templates never contain environment values. Hardcoded passwords and tokens are rejected upon saving.
- **Check stacks from Git:** optionally, Docker checks on a schedule whether the repository has new commits and sends a notification. A button checks immediately.
- **Security updates:** Deck flags a detected security update once in red, and via notification channel also as a push alert. The owner can provide consent with password and two-factor code for Deck to install security updates automatically in the future.
- **Update category:** for each new version, Deck states what it brings: security update, bug fixes, new features, or improvements.
- **Push notifications for security updates:** they can be toggled per category and assigned a priority.

### Fixed

- **Phone:** cards instead of tables in "Docker", "Shield", "Inventar" (Inventory), "Gameserver" (Game servers), "Meldungen" (Notifications), "Aktionen" (Actions), and "Dateien" (Files). The server list fits the screen, the copy button for the join code no longer overflows the card, and the browser bar no longer covers the bottom of the page.
- **Proxmox:** for running guests, the server list displays CPU, memory, and uptime instead of dashes; the console button remains visible; invalid metrics affect only the respective server. Nodes and LXC containers also display disk usage.
- **Nginx Proxy Manager:** expired certificates appear only once in the list, showing the elapsed time since expiration.
- **Updates:** approved updates remain installable even when older version metadata loads slowly. Switching between Stable and Beta channels does not duplicate security notifications, and an in-progress update check does not overwrite recently saved approval consent.
- **Docker page:** results, errors, and rejection reasons stay visible after reloading, including after third-party approval and when collapsing the container section.
- **Renamed modules:** modules locate their stored files even if only an empty directory exists under the new name.
- **Apps:** a detected service that already exists as a custom app with the same address is no longer listed twice.
- **Push delivery:** releases the database connection prior to sending.
- **Nodvard Dock:** dedicated name in title, login, and setup; no general server picker in the console; the "Updates" page checks for its own image; no toggle for autonomous security updates.

### Improved

- **Login page:** errors appear directly at the input field; keyboard navigation and readability are improved.
- **Server health:** CPU frequency with average, minimum, and maximum; human-readable MHz values per core.
- **Docker:** containers can be sorted by state, status, CPU, or RAM.
- **Interface:** service pages feature buttons at the top instead of links; documents include a "+ Tag" button; unread messages show a coloured bar; the timezone list is collapsed; the setup wizard copies commands via button; a server without access directly links to "Zugang einrichten" (Set up access).
- **About page:** help and licence details appear directly below the installation info; in the "Änderungsprotokoll" (Changelog), only the current version is expanded by default.
- **Shield helper:** smaller and clearer; the setup command is shorter. Immutable operating systems like Bazzite or Fedora Atomic receive instructions instead of an error message.
- **Guides:** initial setup restructured with a quickstart section; new guide for Tailscale; privacy sections for Jellyfin, Plex, and qBittorrent; project overview in German and English; guide for Nodvard Dock.
- **Deployment:** deployment, backup, and restore operations abort with an explanatory notice if a version older than 0.6 is still present on the machine.

### Good to know

- **Nodvard Dock:** published as a separate image with its own guide.
- **Complete list:** all changes can be found in Nodvard Deck under "Einstellungen" (Settings), "Über Nodvard Deck" (About Nodvard Deck), "Änderungsprotokoll" (Changelog).
