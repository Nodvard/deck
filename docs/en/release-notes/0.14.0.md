# Nodvard Deck 0.14.0: Shield becomes a security centre, SSH hardening at the press of a button, and a large wave of hardening

## English

The web interface is in German only for now. Names of buttons, tabs, pages, and settings are given in German as they appear, with an English translation in brackets.

### The essentials

The largest release so far by volume. Nodvard Shield grows into a real security centre, the whole interface is now usable on a phone, and a large wave of hardening and fixes went in across Docker, SSH, login, and the update chain. It contains fewer new showcase features than improvements on the inside. If you want to keep your homelab secure and tidy, 0.14 is the right release.

- **Shield:** configure Fail2ban per server, match packages against public security advisories (CVE), weekly security reports, SSH hardening at the press of a button, and a read-only check of open ports and certificates from your home network (not from the internet).
- **SSH hardening:** switch a server to key-only login with one click, root password login off, with an automatic 60-second rollback and a warning if Deck would lock itself out.
- **Phone:** second wave of cards. Overview, Proxmox, Synology, backups, registries, Shield packages, inventory, and documents show their entries as cards.
- **Docker:** clean up unused images (with total size and freed space), hardened templates, stacks from Git with their own process and limits, safe rollbacks.
- **Nodvard KI (Nodvard AI):** besides Ollama, now also OpenAI-compatible providers, with a fallback model, a connection test, and a notice when data leaves your network.
- **Usage data:** voluntary, in three levels, off by default, with a log of what was sent and a delete button.

### What you need to do

- **Repeat server setup once:** because of the new Shield helper script and the sudo rule from 0.13, existing servers have to be set up once more after the update. Only then do Fail2ban, CVE matching, and SSH hardening work. The weekly report, Fail2ban, and SSH hardening appear only once a server has been set up with the current helper.
- **Renew the update helper and store the signing key (only with an update helper):** From 0.14.0 on, Deck sends updates and rollbacks only in signed form, and the helper executes only signed requests. After the update, the buttons "Jetzt aktualisieren" (Update now) and "Zurück zu Version ..." (Back to version ...) stay locked until you have renewed the helper and stored this installation's public key in it. The card names the reason. You are not locked out: your data and access stay, and updating by hand still works. The steps are in [deploy/README.md](../../../deploy/README.md#schlüssel-für-update-anforderungen) in the section "Schlüssel für Update-Anforderungen" (Key for update requests): first renew the helper image (`docker compose pull updater`, then `docker compose up -d updater`), then create the key and place it in the helper. **Without an update helper**, nothing changes for you.

### Security

- **SSH hardening at the press of a button:** key-only login, root password login off, automatic 60-second rollback if the confirmation does not arrive, and a warning if Deck would lock itself out.
- **Signed update requests:** Deck signs every request to the update helper with its own key per installation. The helper additionally requires the release approval and rejects missing, forged, repeated, and expired signatures. The rollback is signed as well.
- **Compose treats everything unknown as risky:** if the image, command, or user of a service that already has docker.sock or privileged rights changes, this remains a high-level approval. Folders are resolved on the server so that a link to a system folder does not pass as a data folder.
- **Hardened defaults:** the Compose templates run the container without root, with a read-only root file system and without additional rights. Stacks from Git determine their environment files in a separate process with fixed limits for memory and runtime.
- **Login:** after 30 wrong passwords in five minutes, further attempts are blocked only from foreign networks (IPv6 networks grouped). Someone who knows your user name can no longer lock you out of your home network from the internet. A race during login renewal is fixed.
- **Strict API:** unknown fields and wrong JSON types are rejected, plus a stricter content security policy and referrer rule.
- **Update chain:** component list (SBOM) and provenance for every version, a signing tool without the redirect leak, and Debian security updates in the image.
- **SSH and servers:** access only with an unambiguous target, a pause after three rejected SSH logins (30 minutes to 6 hours, survives a restart), merging of servers with key comparison, and a separate state "SSH fehlt" (SSH missing).

### New

- **Shield, Fail2ban per server:** set ban time, find time, attempts, and exceptions, and select jails, with a check before activation and protection against locking yourself out.
- **Shield, CVE matching per server:** installed packages are matched against public security advisories, with severity, fixed version, and a link to the update centre.
- **Shield, weekly report:** twelve weeks of history per server (updates, virus scan, Fail2ban bans, Lynis hardening score), with a short version sent through your notification channels.
- **Shield, external check from the home network:** Deck checks open ports and HTTPS certificates from your home network, not from the internet, and warns about newly open ports, certificates that expire soon or are self-signed, and weak TLS protocols. Read-only, on a schedule, can be switched off.
- **Nodvard KI (Nodvard AI) with OpenAI-compatible providers:** usable besides Ollama, with a fallback model, a connection test, and a notice when data leaves your network.
- **Voluntary usage data:** three levels, off by default, with a log of what was sent and a delete button.
- **Docker, clean up images:** the "Images" tab shows the total size of all images and, after confirmation and approval, removes unused images without a name. Afterwards it states how many were removed and how much space was freed.

### Fixed

- **Backups:** without backups, the overview shows a grey notice instead of a green success; empty lists show "Keine Sicherungsjobs gefunden" (No backup jobs found).
- **Shield:** running Fail2ban values instead of deviating stored settings; a failed reload after installation is reported as an error.
- **Docker:** results and rollbacks are kept after aborts and restarts, stacks from Git briefly check the services after deployment, and the deletion protection for stack folders also applies across links.
- **Files:** incomplete partial downloads are detected as errors, and the live connection no longer opens a duplicate connection.
- **Usage data:** renamed modules are recognised correctly, and deletion requests still reach the previous recipients after a change of recipient.
- **Automatic checks:** virus scans, background checks, and resumed tasks now run with matching access contexts instead of being skipped silently.

### Improved

- **Phone:** stack cards show only the most important buttons and a more menu.
- **Docker:** on a network, the button is now called "Container verbinden" (Connect container), missing stack values can be entered directly (passwords hidden, only for this stack), and when stopping a stack you can choose whether containers remain.
- **Servers:** common tags through checkboxes with a short explanation; your own tags remain possible.
- **Update centre:** the search is at the top, and the guide for updating by hand appears only when expanded.
