# Nodvard Deck 0.14.3: security and fixes

## English

The web interface is in German only for now. Names of buttons, tabs, pages, and settings are given in German as they appear, with an English translation in parentheses.

### The essentials

A bugfix release focused on security, with one small relief in Shield for many findings in the same folder. Bigger changes come with the next version.

- **Tighter permissions:** Accounts with limited permissions now only see and do what matches their permissions. This affects Shield, the audit log, and live messages.
- **Login:** A copied login ends as soon as your own device checks in again. After a password change, a login that was already started can no longer be completed with the two-factor code.
- **Credentials:** Stored credentials can no longer be deleted, pointed elsewhere, or used with weaker certificate checking without the password.
- **Backups:** Running a job again only backs up guests that belong to the job, and a download link for a backup only works for your own login.
- **File manager:** Uploads to a server no longer follow links that belong to someone else.

### What you need to do

Nothing special. With the update helper, update as usual via "Jetzt aktualisieren" (update now).

Only if you gave other accounts limited permissions:

- Whoever should trigger updates, restarts, installs, the virus guard, quarantine, or Fail2ban bans in Nodvard Shield now also needs the permission to run commands on servers. This also applies with full automation. Without it, findings from a virus scan they start themselves stay open and carry a note.
- Error messages and other text coming from the servers appear in the audit log only for accounts with this permission.
- Excluding a folder from scans with one click in Shield is only allowed for accounts that may also manage modules.
- A running automatic backup can only be cancelled by the owner account.

Only if Deck is signed in to a server as root: the file manager no longer uploads directly into folders that belong to another user of that server. Upload the file into a folder owned by root and move it there, or connect Deck with the account of the folder owner.

### Security

- **Shield:** Updates, restart, install, the virus guard, moving files to quarantine, restoring and deleting them, and Fail2ban bans can only be triggered by someone who may also run commands on servers. This also applies with full automation.
- **Shield:** If someone without this permission starts a virus scan, Shield does not move the findings to quarantine by itself. Scheduled scans keep moving them as configured.
- **Shield:** The server name from a rejected AI answer is shortened and cleaned before it appears in the audit log.
- **Audit log:** Accounts without the permission to run commands on servers no longer see error messages and other text coming from the servers. IDs, names, and numbers stay visible.
- **Accounts:** Whoever may not manage other accounts no longer sees their names and roles in the audit log and gets no messages about other accounts.
- **Live messages:** Live updates from modules only reach accounts that may see the matching tile. If permissions are taken away from an account, this also applies to messages that are already on their way.
- **Live messages:** A stalled browser tab no longer delays messages in other tabs. An account can keep at most 20 live connections open at once, each open tab counts as one.
- **Login:** If a login that was already renewed shows up again later, Deck ends this login with all its renewals and notes it in the audit log.
- **Login:** If a password is changed or reset, a login that was just started with the old password can no longer be completed with the two-factor code.
- **Credentials:** Stored credentials of Proxmox VE and Proxmox backups can no longer be deleted or pointed to another address through the connections without the password.
- **Credentials:** Whoever turns off certificate checking, enters a different fingerprint, or removes the remembered one for a module with stored credentials now confirms this with the password.
- **Backups:** Running a Proxmox backup job again only backs up guests that belong to this job.
- **Backups:** A running automatic backup can only be cancelled by the owner account. Every cancellation and every rejected attempt is in the audit log.
- **Backups:** A download link for a backup only works while you are signed in on this device and your password stays the same.
- **File manager:** When uploading to a server, the file manager only follows links and uses folders in the target path if they belong to root or to the account Deck uses on that server. Signed in as root, an upload into the folder of another user therefore no longer works; the message explains how to continue. On Windows servers Deck only checks the reported write permissions, not the owner of the folders.
- **Modules:** Modules can no longer start actions, commands, terminals, or consoles directly through other modules and bypass approvals and logging that way.

### Fixed

- **Shield:** If many open findings sit in one folder, the Quarantäne (quarantine) tab shows a note and offers to exclude the folder from scans and close the findings in it. This also covers its subfolders. System folders and folders other accounts on this server can write to cannot be excluded this way. The note appears from 10 open findings in the same folder. The exclusion applies to all servers, not only the one with the findings, and you have to confirm that separately. The real-time guard only picks it up after you turn it off and on again. The closed findings can be reopened all at once, even with more than 200 findings.
- **Shield:** New findings show up under the right server even if it was merged with another entry during the scan.
- **Shield:** If a long virus scan is cut off before it finishes, for example at the 4 hour limit of the deep scan, the note on the scan and on its findings now says that the scan was cut off. Until now it wrongly mentioned a line break in a file name.
- **Proxmox:** Unreachable storage is shown clearly in the tile and list. The watcher reports the outage once and sends an all-clear when the storage is reachable again.
- **Proxmox:** Connections of Proxmox VE or Proxmox backups whose name starts or ends with a space can be removed again. Deck no longer accepts new connections with such a name and says why.
- **Backups:** Jobs and connections with two hyphens in a row in the name are no longer mixed up with another job. Backup checks handle NVMe disks correctly.
- **Docker:** Image updates always run in the project folder of the stack, so ${PWD} and relative paths are resolved correctly even without saved variables.
- **Docker:** The Docker module protects the Nodvard Deck container even with a custom hostname, detects Portainer folders more precisely, and counts crashed stack containers as a problem. If Docker folders cannot be read in the file manager, the reason is in the audit log.
- **Nginx Proxy Manager:** If it runs under a path, the path is kept. If it still answers 502, 503, or 504 while starting, Deck says it is still starting instead of showing a login error.
- **Uptime Kuma, ntfy, Nextcloud files:** When a service is unreachable, short German sentences appear instead of English error texts.
- **Valheim:** The server uses the default world name, keeps server names with hyphens, and no longer shows old player counts when the service is stopped.
- **Modules:** Saving module settings keeps concurrent changes to hidden values of the module. Faulty message types of an extension no longer block the settings.
- **Interface:** With too many tabs open, the interface no longer keeps reconnecting but shows a note with "Erneut verbinden" (reconnect).
