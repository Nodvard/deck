# Nodvard Deck 0.12.0: Docker stacks from Git, Fail2ban in Nodvard Shield, and tighter limits for modules and logins

## English

The web interface is in German only for now. Names of buttons, pages, and settings are given in German as they appear, with an English translation in brackets.

### The essentials

- **Docker stacks from Git:** deploy a stack from a Git repository, with a preview of every change and a way back to the previous state.
- **Fail2ban in Nodvard Shield:** see banned addresses per server, unban them, or ban an address yourself.
- **Security:** one-click updates only for versions with a signed release approval, throttling of password guessing, and tighter limits for modules.
- **No database migration.**
- **Some installations need attention afterwards**, see "Was du tun musst" (What you need to do).

### What you need to do

1. **Servers that get root rights only through helper scripts:** run the setup command again. Nodvard Shield ships a new helper script and blocks actions that need root on those servers until then. Servers with a full sudo rule or root login need no action.
2. **Rename `LATTICE_*` to `NODVARD_DECK_*`.** The old names still work in 0.12 and will stop working in one of the next versions, 1.0 at the latest. The home page shows the owner which ones the container still sees. In the `.env` file next to the Compose file, rename by hand: `LATTICE_PORT` → `NODVARD_DECK_PORT`, `LATTICE_DNS_1` → `NODVARD_DECK_DNS_1`, and `LATTICE_DNS_2` → `NODVARD_DECK_DNS_2` (the home page cannot show these, because only Compose reads that file).
3. **Remove the old full sudo rule (recommended).** Servers set up before 0.11.1 with "Root-Rechte ohne Passwort" (Root rights without password) often still have `<user> ALL=(root) NOPASSWD: ALL`. Once no module needs the rule anymore, the overview points it out under "Braucht Aufmerksamkeit" (Needs attention) and links to the ready-made setup command with "Volle sudo-Regel entfernen" (Remove full sudo rule).

   **Remove it by hand**, only once "Verbindung prüfen" (Check connection) shows "Eigene sudo-Regel vorhanden" (Own sudo rule present) for every helper script (`<user>` is the SSH user Deck logs in with):

   ```bash
   sudo rm -f /etc/sudoers.d/nodvard-<user> /etc/sudoers.d/lattice-<user>
   ```

   Then run "Verbindung prüfen" (Check connection) again. Details: [FIRST-SETUP.md, section F](https://github.com/nodvard/deck/blob/main/docs/en/FIRST-SETUP.md#f-root-rights-without-a-password-and-the-docker-group).
4. **Check third-party extensions and your own scripts.** The old names `lattice` and `lattice_sdk` (Python packages), `LatticeExtension` and `LatticeError` (classes), and the entry point group `lattice.extensions` are gone. Deck no longer loads extensions that still use them. The extension list shows which ones are affected, why, and what helps. Change your own scripts from `import lattice` or `python -m lattice.…` to `nodvard_deck`. An extension's interface needs `window.__nodvardDeck` instead of `window.__lattice`.

### New

**Docker: Stacks from Git**
- A stack that Deck manages (created in Deck or adopted with "Übernehmen" [Adopt]) can use a Git repository as its source, only via `https://`.
- Before each apply, you see which files would be new or changed, including the diff of the Compose file and notices about anything not coming from the repository.
- Changes are applied after a confirmation and approval, with the permissions of the stack folder's owner.
- If Compose rejects the new state, the previous state is restored on the server immediately.
- "Zurück zum Stand davor" (Back to previous state) restores the state before the last apply and only removes files that Deck wrote itself and that nobody has changed since.
- Deck never replaces existing environment files such as `.env`, and only removes one it created itself upon "Zurück zum Stand davor" (Back to previous state).
- Only the services from the approval are restarted, and for additional ones there is "Jetzt neu starten" (Restart now) with its own approval.
- After restarting, Deck verifies that the services run stably, including those that were stopped beforehand.
- Stack volumes can be backed up beforehand, during which the services using them are stopped.
- Restoring is available in the "Stacks" (Stacks) tab under "Sicherungen" (Backups).
- Git credentials for private repositories are configured in the Docker module settings, and their token is stored in the vault ("Tresor") and only sent to the registered server.

**Nodvard Shield**
- Intrusion protection: per server, you see the addresses banned by Fail2ban, can unban them, and can ban addresses yourself.
- The IP address of your browser and the address through which Deck reaches the server cannot be banned, ensuring no one locks themselves out.
- Update center: for Ubuntu servers, the count of updates still being phased out is displayed ("Phasing"), with a short explanation.
- Update center: "Alle einspielen" (Install all) only installs phased updates once it is the server's turn, and points this out beforehand in the confirmation prompt.

**Servers and sudo**
- "Volle sudo-Regel entfernen" (Remove full sudo rule) under "Erweitert" (Advanced) in the setup command checks each helper script before and after, and immediately restores the rule in case of an error.
- The new checkbox "Volle sudo-Regel gewollt" (Full sudo rule intended) on the server is for anyone running custom commands with sudo through Deck.

**Settings**
- If the owner logs in via a proxy on the local network that is not registered as trusted, a notice appears, as Deck cannot see the real client addresses without such an entry.

### Security

**Updates**
- Deck only offers "Jetzt aktualisieren" (Update now) for versions approved at release with the project's signing key.
- A current update helper verifies the signature of this approval itself and rejects an invalid one. The signature only becomes mandatory for every update with 1.0, see "Gut zu wissen" (Good to know).
- With a current update helper, "Jetzt aktualisieren" (Update now) installs exactly the version verified by the update search.
- If the update has changed since, the button downloads nothing and prompts for a new update search.

**Logins**
- Access tokens become invalid immediately upon logout, password change (for other sessions), and deactivation or reactivation of an account, instead of remaining valid for up to 15 minutes.
- After 10 failed login attempts for a username within 24 hours, each subsequent attempt from the same network waits twice as long as the previous one, up to 5 minutes, and you receive a notification.
- The throttling applies per network: you can still log in immediately from your home network, via VPN, and from other networks.
- Against attackers with many different addresses, a long password and two-factor authentication continue to help.

**Browser**
- Camera, microphone, location, and other devices Deck never uses are blocked in the browser.
- External sites can no longer embed Deck, except for the logo, icons, and reachability check.
- The interface loads images, data, and connections only from its own server, and the browser now blocks external addresses instead of merely reporting them.

**Modules**
- Through their database connection, modules only reach their own tables, no longer accounts, the vault, or the audit log.
- A module only receives a secret from the vault if it has the explicit permission for that exact secret, not via detours, and never the two-factor keys of user accounts.
- From dashboard settings, modules only read the timezone and maintenance window, no longer approval rules or the list of trusted proxies.
- If a module is restricted to specific IP ranges, it cannot bypass them using hostnames.
- Which command ran after an action is only visible to the proposing module and modules permitted to execute commands themselves.
- As the actor in the audit log, a module can only name the person who was actually involved.
- If an installed extension wants to adopt data from a removed module, an administrator must allow this under "Einstellungen" (Settings) → "Erweiterungen" (Extensions).

**Servers and helper scripts**
- Helper scripts are only placed in directories that nobody but root can write to, not even a group.
- If the directory is too permissive, setup states the reason and remedy, and "Verbindung prüfen" (Check connection) warns on already configured servers.
- Docker: if a server has been set to "Nur bedienen" (Operate only), a proposed action is no longer executed, except for starting, stopping, and restarting containers.
- Docker: if a server is no longer marked as a Docker server, no proposed Docker action is executed there anymore.
- Docker: after repeating setup, "Nur bedienen" (Operate only) always uses Docker on the server itself, even if root points to another Docker daemon via `DOCKER_HOST` or Docker context.

**Nodvard Shield**
- Without a helper script, a file only moves to quarantine if ClamAV reports it again as a detection during the attempt.
- From quarantine, a file is only restored to its original location with its original permissions, even without a helper script.
- The confirmation and approval prompt for restoration state "an den hinterlegten Ort" (to the stored location), and the result names the location where the file actually went.
- Files quarantined with Deck 0.8 or older must be restored or deleted manually instead of via button, because their original location is missing.
- Incidents can only be managed by users permitted to administer Shield (`soc.manage` permission); with `soc.read` alone, they remain read-only.

**Other**
- If a backup fails due to missing write permissions, the user ID and command only appear under "Einstellungen" (Settings) → "System" (System), not in the audit log or notification.
- Document text recognition (Tesseract) receives the latest security updates with each new version.
- The built-in Git library has been updated and no longer crashes on deliberately malformed Git data.

### Improved

- **Initial setup:** two-factor setup can be skipped with "Später einrichten" (Set up later), even after selecting "Jetzt einrichten" (Set up now).
- **Modules:** if a module crashes on startup, the reason is clearly explained, offering the buttons "Neu starten" (Restart) and "Ausschalten" (Turn off).
- **Updates:** the "Updates" (Updates) card shows whether a new version is approved and whether your update helper verifies approvals itself.
- **Update helper:** the Compose file for the helper is attached to each release on GitHub and states the checksum of the verified helper.
- **sudo:** "Verbindung prüfen" (Check connection) and the overview highlight an unnecessary full sudo rule and link directly to the matching setup command.
- **Backups:** if write permissions for the backup folder are missing, "Einstellungen" (Settings) → "System" (System) displays user, owner, and the command to resolve it.
- **Backups:** if write permissions are missing, the push notification and job log also indicate where to find guidance.
- **Pi-hole and Nginx Proxy Manager:** if the service is unreachable, a German sentence explains the cause and next step instead of an English error message.
- **Home page:** widgets only display buttons for which you have permissions.
- **Home page:** the owner sees which `LATTICE_*` settings are still configured and what their new names are.
- **Logins:** long-expired or terminated sessions, including IP address and browser info, are purged every night.
- **Audit log:** when a module proposes an action on behalf of automation, a schedule, or a user, the entry includes the module name.
- **Interface:** Deck detects a new version of its home page by content rather than file size and timestamp, allowing exactly its embedded scripts immediately.
- **Licences:** the licence list states the chosen licence for dual-licensed components and lists the operating system packages inside the image.
- **Documentation:** a table explains what helper scripts may do as root, and the file watcher section documents what root reads from monitored files.

### Fixed

- **Overview with many widgets:** now loads reliably instead of aborting after half a minute with a database error. Thanks for the report!
- **Vault:** a new password, token, or key takes effect immediately for qBittorrent, Synology DSM, Pi-hole, Nginx Proxy Manager, Home Assistant, Jellyfin, Plex, Nextcloud, and Uptime Kuma, and a pause after a rejected login ends immediately. Previously, depending on the module, the previous values remained in use for up to 30 minutes or until someone saved settings or clicked "Verbindung testen" (Test connection).
- **Pi-hole and Nginx Proxy Manager:** "Verbindung testen" (Test connection) logs in again each time, thereby catching an incorrect new password.
- **Approvals:** expired approvals are labelled "Abgelaufen" (Expired) and can only be dismissed.
- **Docker:** a server tagged with both "docker" and "docker-bedienen" is treated as a full Docker server.
- **Docker:** setup, "Verbindung prüfen" (Check connection), and overview now report a missing Docker helper script as an issue.
- **Docker:** "Verbindung prüfen" (Check connection) and overview now accurately display that an older helper script continues running until setup is repeated.
- **Docker:** if a server lacks the "docker" tag, image updates, stack actions, Portainer migration, and registry login provide the reason instead of simply "Kein Docker-Host." (No Docker host).
- **Docker:** if restoring a volume backup aborts before swapping data, the stack runs again and the half-extracted directory is removed.
- **Docker:** if a stack remains stopped after such an abort, a notification states the reason and next step.
- **Docker:** an unexpected response from a registry only marks that specific image as uncheckable, not the entire server.
- **Helper scripts:** for an ACL on the helper script directory, setup now recommends `setfacl -b` followed by `chmod g-w` as the remedy (`setfacl -b` alone was insufficient).
- **Nodvard Shield:** files with permissions such as 044 or 000 can once again be restored from quarantine (on servers with helper scripts only, after repeating setup).
- **Synology DSM:** Hyper Backup integrity checks are no longer treated as errors.
- **Setup:** if you disabled Deck's key on a server using `#`, repeating setup restores it in working order.
- **Jobs:** daily cleanup of old job runs no longer aborts on an unusable filename originating from a restored backup.
- **Display:** Docker stacks with many buttons wrap properly, date and time always appear in German format, and inventory and proxy notices are phrased correctly.

### Good to know

- **Updating:** "Einstellungen" (Settings) → "Updates" (Updates) → "Jetzt aktualisieren" (Update now), or `docker compose pull && docker compose up -d`. Updating manually continues to work without approval.
- **Key for approvals:** the public key has the ID `916fff4eb943eb5d`. You configure the update helper with the Compose file attached to this release.
- **Signature transition:** until 1.0, the update helper also accepts requests without approval, for example from an older Deck version. If an approval is provided, it verifies its signature. Starting with 1.0, it will only install updates with a valid signature.
- **Open browser tabs:** a tab opened prior to the update must be reloaded once when opening a module page for the first time; the page provides a button for this.
- **Extensions with legacy interface:** if only the interface of an extension uses legacy names, its page will be missing until its author publishes a new release.
- **Nodvard Dock 0.12.0 (Beta)** also includes stacks from Git and features its own release notes.
