# Nodvard Deck 0.12.1: Bestätigung neuer Server-Schlüssel und Korrekturen in der Update-Zentrale

## Deutsch

### Das Wichtigste

Ein Patch-Release mit Fehlerbehebungen und einer Sicherheitskorrektur.

- **Neue Server-Schlüssel:** Deck merkt sie sich auch bei bestehenden Installationen erst nach deiner Bestätigung.
- **Update-Zentrale:** Zurückgehaltene und gesperrte Pakete erscheinen als eigener Zustand mit einer Erklärung.
- **Ubuntu-Updates:** Deck zeigt an, wenn die Prüfung der schrittweisen Verteilung noch aussteht oder fehlgeschlagen ist.

### Was du tun musst

- **Noch unbekannte Server:** Wähle beim Server einmal „Verbindung prüfen“ und bestätige den angezeigten Fingerabdruck. Bereits bekannte Server laufen wie gewohnt weiter.

### Sicherheit

- **Bestätigung neuer Server-Schlüssel:** Auch bei älteren Installationen merkt sich Deck neue Server-Schlüssel erst nach deiner Bestätigung. Ohne Nachfrage merkt Deck sie sich nur noch, wenn du die Bestätigung ausdrücklich ausschaltest, unter Einstellungen → Server & Zugänge oder über die Umgebungsvariable NODVARD_DECK_SSH_CONFIRM_NEW_HOST_KEYS. Das ist nicht empfohlen.

### Behoben

- **Zurückgehaltene und gesperrte Pakete:** Updates, die „Alle einspielen“ nicht einspielen kann, erscheinen nicht mehr wie offene Updates. Deck zeigt sie als „zurückgehalten“ oder „gesperrt“ und erklärt den nächsten Schritt. Gibt es nur zurückgehaltene Sicherheitsupdates, erscheint kein Knopf „Sicherheitsupdates einspielen“.
- **Sicherheitsupdates einspielen:** Der Lauf entfernt keine anderen Pakete mehr. Zurückgehaltene, gesperrte und durch Phasing verzögerte Sicherheitsupdates bleiben stehen. Vor dem Einspielen prüft Deck den Server erneut.
- **Phasing bei Ubuntu:** Ist noch unbekannt, ob Ubuntu Updates für den Server verzögert, zeigt Deck „Phasing noch nicht geprüft“ oder „Phasing-Prüfung nicht verfügbar“. Eine ausstehende oder fehlgeschlagene Prüfung lässt den Hinweis nicht mehr verschwinden.

### Gut zu wissen

- **Zurückgehaltene Pakete:** Müssen dafür andere Pakete ersetzt oder entfernt werden, brauchst du auf dem Server `sudo apt full-upgrade`. Lies vor dem Bestätigen die Liste der Pakete, die apt entfernen würde. „Alle einspielen“ lässt diese Updates stehen.
- **Gesperrte Pakete:** Eine bewusst gesetzte Paketsperre bleibt bestehen. War sie nicht beabsichtigt, kannst du sie auf dem Server mit `sudo apt-mark unhold <Paketname>` aufheben.
